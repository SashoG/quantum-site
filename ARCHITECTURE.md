# Quantum Electronics Department Website — Architecture

**Site:** https://quantum.phys.uni-sofia.bg
**Owner:** Катедра „Квантова електроника“, Физически факултет, СУ „Св. Климент Охридски“
**Status:** Design agreed internally — Hugo + Pages CMS + GitHub + static hosting on the Faculty of Physics server (Apache). Hosting details pending sysadmin answers (§16).
**Revision:** 2 (see §18)

---

## 1. Goals

1. Replace the legacy frameset/HTTP site with a modern, responsive, fast, accessible site.
2. Preserve all existing content and extend it.
3. Give every lecturer a personal space (profile, courses, lecture materials) editable through a web UI, without Git, Markdown or developer tools.
4. Zero server-side runtime on the faculty server: static files only → nothing to patch, minimal attack surface for the wider `phys.uni-sofia.bg` domain.
5. Easy to build and maintain with AI tooling (Claude Code); easy handover (low bus factor).

## 2. Key decisions

| Area | Decision | Rationale |
|---|---|---|
| Site generator | **Hugo** (pinned version) | Single binary, no `node_modules`, built-in i18n, stable for years |
| Source of truth | **Git repository on GitHub** (department organization) | Full history, every change reversible, free CI |
| Editing UI | **Pages CMS, hosted** at app.pagescms.org | Colleagues invited by email, no GitHub account needed; edits become commits |
| Build | **GitHub Actions** | Builds on every commit; nothing to install on the server |
| Hosting | **Faculty of Physics server, Apache**, static files only | Provided by the faculty; HTTPS under `phys.uni-sofia.bg` |
| Deploy | **Pull model**: server cron pulls the built site from a `deploy` branch | Needs only outbound HTTPS from the server; firewall-friendly |
| Server config | **vhost only, `.htaccess` disabled** (`AllowOverride None`) | Repository content can never change server configuration |
| Styling | Plain modern CSS (custom properties, grid/flex), Hugo Pipes | No Node toolchain to rot |
| Languages | Bulgarian (default, `/`) + English (`/en/`) | Bilingual audience |
| Old URL redirects | Not planned | Old site is HTTP-only with weak SEO; can be added later in the vhost if needed |

## 3. What the server hosts

Only static files, served as-is, never executed on the server:

- **HTML** pages generated by Hugo
- **CSS**
- **Front-end JavaScript** (runs in the visitor's browser only): mobile menu, search, optional KaTeX
- **Images**: jpg, png, webp, svg
- **Fonts**: woff2
- **Materials**: PDF lectures; zip, docx, pptx, xlsx; short optimized video (mp4/webm)
- **Generated service files**: `sitemap.xml`, RSS `index.xml`, `robots.txt`, favicon, search index JSON

No PHP, CGI, SSI or database.

## 4. High-level architecture

```
 Lecturer / editor (browser)              Maintainer (Claude Code, local)
          │                                          │
  app.pagescms.org ── commit via GitHub App ─┐  git push
   (hosted SaaS)                             ▼       │
                         GitHub repo  (branch: main) ◄┘
                                           │
             GitHub Actions: file allowlist check → hugo --minify
                                           │
                         push built site → branch: deploy
                                           │
     Faculty server (Apache): cron, fixed interval → git fetch/reset → docroot
                                           │
                      https://quantum.phys.uni-sofia.bg  (static)
```

Optional: a staging preview on GitHub Pages / Cloudflare Pages built from `main` for review before go-live.

## 5. Pages CMS hosting

- **Default: hosted SaaS** at app.pagescms.org, run by the Pages CMS maintainers. Not on the faculty server, not on GitHub.
- The Pages CMS GitHub App is installed on **this repository only**.
- **Content** (Markdown, PDFs, images) lives **only in the GitHub repository**. Pages CMS reads and writes it through the GitHub API; it does not keep a copy.
- **Pages CMS stores**: invited collaborators' emails, sessions, encrypted GitHub tokens.
- The faculty server is not involved in editing at all.

**Risks and fallback**
- Third-party dependency: if the service disappears, content is intact; only the editor is lost. Fallback: self-host Pages CMS or switch to Sveltia CMS (same Markdown files; only the CMS config changes).
- Colleagues' work emails are stored by an external provider — department head should be informed.

**Self-hosting (only if needed later)**: Next.js app + PostgreSQL + own GitHub App. Realistic target: Vercel (or similar) + managed Postgres. **Not** on the faculty server — it would reintroduce a dynamic application with a database.

## 7. Content model

All content is Markdown with YAML front matter. Pages CMS presents each collection as a form.

### 7.1 Person — `content/<lang>/people/<slug>.md`

```yaml
title: "гл. ас. д-р Александър Гайдарджиев"
slug: "gaydardzhiev"
position: "главен асистент"        # select: професор, доцент, гл. ас., ас., докторант, ...
degree: "д-р"
photo: "/images/people/gaydardzhiev.jpg"
email: ""
office: ""
phone: ""
research_interests: ["нелинейна оптика", "матрична оптика"]
links:
  scholar: ""
  orcid: ""
weight: 30                         # ordering on the staff page
active: true                       # false → listed under former staff
```
Body: biography, selected publications.

### 7.2 Course — `content/<lang>/courses/<slug>.md`

```yaml
title: "Матрична оптика"
lecturers: ["gaydardzhiev"]        # references to person slugs
programme: ["Фотоника и лазерна физика"]
type: "избираема"                  # задължителна / избираема / факултативна
semester: "зимен"
ects: 0

  - title: "Лекция 1 — Лъчева матрица"
    file: "/materials/gaydardzhiev/matrix-optics-lecture-01.pdf"
    date: 2026-10-01
```
Body: syllabus, assessment, literature.

The person page lists all courses whose `lecturers` contain the person's slug (Hugo `where` query) — this is the lecturer's personal space.

### 7.3 News — `content/<lang>/news/<yyyy-mm-dd>-<slug>.md`

### 7.4 Research / lab — `content/<lang>/research/<slug>.md`

## 10. Media and file policy

| Item | Policy |
|---|---|
| Lecture materials | PDF preferred, ≤ 20 MB per file, in `static/materials/<person-slug>/` |
| Images | Resized by Hugo image processing; originals ≤ 5 MB |
| Video | Preferably external links (YouTube / Moodle). Short optimized clips allowed: mp4/webm, ≤ 25 MB |
| Repository budget | Keep total < 1 GB; GitHub hard limit is 100 MB per file |
| Naming | lowercase, Latin, hyphens: `matrix-optics-lecture-01.pdf` |
| Not allowed | html, htm, svg, js, php, sh, exe, `.htaccess`, any other type not on the allowlist; symlinks |

If the repository approaches its budget, move old course materials to a yearly archive folder on the faculty server and link to them.

## 11. Build and deploy

### 11.1 CI allowlist check — `scripts/check-files.sh`

Runs before every build; the build fails on any violation, so nothing reaches the server.

```sh
#!/bin/sh
set -eu
fail=0

# 1. No symlinks anywhere in the repository
if git ls-files -s | awk '$1 == "120000"' | grep -q .; then
  echo "ERROR: symlinks are not allowed"; fail=1
fi

# 2. Materials: allowlisted extensions only
bad=$(find static/materials -type f \
  ! -iregex '.*\.\(pdf\|zip\|docx\|pptx\|xlsx\|mp4\|webm\|jpg\|jpeg\|png\)$' || true)
[ -n "$bad" ] && { echo "ERROR: disallowed files:"; echo "$bad"; fail=1; }

# 3. No server-side or config files anywhere in static/
bad=$(find static -type f \( -iname '*.php*' -o -iname '.htaccess' -o -iname '*.cgi' \
  -o -iname '*.shtml' -o -iname '*.sh' \) || true)
[ -n "$bad" ] && { echo "ERROR: forbidden files:"; echo "$bad"; fail=1; }

# 4. Size limit per file (25 MB)
big=$(find static -type f -size +25M || true)
[ -n "$big" ] && { echo "ERROR: files over 25 MB:"; echo "$big"; fail=1; }

exit $fail
```

### 11.2 GitHub Actions — `.github/workflows/deploy.yml` (sketch)

Third-party actions are **pinned by commit SHA**, not by tag.

```yaml
name: build-and-publish
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<sha>            # v4
      - run: sh scripts/check-files.sh
      - uses: peaceiris/actions-hugo@<sha>      # v3
        with:
          hugo-version: "<pinned version>"
          extended: true
      - run: hugo --minify --baseURL https://quantum.phys.uni-sofia.bg/
      - uses: peaceiris/actions-gh-pages@<sha>  # v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public
          publish_branch: deploy
          force_orphan: true                    # deploy branch keeps only the latest build
```

### 11.3 Faculty server — `server/server-pull.sh`

Runs as the **site's own Unix user, never root**. The Git directory is **outside** the docroot. Symlinks are never materialized.

```sh
#!/bin/sh
set -eu
GIT_DIR=/srv/quantum-site.git          # outside docroot
WORK_TREE=/var/www/quantum             # docroot (confirm with sysadmin)
export GIT_DIR

git fetch --quiet origin deploy
if [ "$(git rev-parse HEAD)" != "$(git rev-parse origin/deploy)" ]; then
  git --work-tree="$WORK_TREE" reset --hard --quiet origin/deploy
  git --work-tree="$WORK_TREE" clean -fdq
fi
```

One-time setup:

```sh
git clone --bare --single-branch --branch deploy \
  https://github.com/<org>/quantum-site.git /srv/quantum-site.git
git --git-dir=/srv/quantum-site.git config core.symlinks false
```

**Scheduling** (fixed interval, e.g. every 5 min), in order of preference:
1. User crontab of the site user: `*/5 * * * * /srv/scripts/server-pull.sh`
2. If user crontabs are not allowed: sysadmin adds a system entry, e.g. `/etc/cron.d/quantum`:
   `*/5 * * * * quantum /srv/scripts/server-pull.sh`
3. If outbound HTTPS to github.com is not allowed: push model — GitHub Actions deploys via `rsync` over SSH (requires inbound SSH from GitHub runners and a restricted deploy key).

If the repository is private, use a **read-only** deploy key or a fine-grained read-only token scoped to this repo.

Publication latency: commit → live in ≈ 2–7 minutes.

## 12. Apache configuration (vhost)

All server behaviour is set **once by the sysadmin in the vhost**, not in the repository. Reference fragment (kept in `server/quantum-vhost.conf`, adjust paths):

```apache
<VirtualHost *:80>
    ServerName quantum.phys.uni-sofia.bg
    Redirect permanent / https://quantum.phys.uni-sofia.bg/
</VirtualHost>

<VirtualHost *:443>
    ServerName quantum.phys.uni-sofia.bg
    DocumentRoot /var/www/quantum
    # SSL directives as per faculty standard

    <Directory /var/www/quantum>
        AllowOverride None
        Options -Indexes -FollowSymLinks -ExecCGI -Includes
        Require all granted
    </Directory>

    # No server-side execution in this vhost (if PHP is loaded globally)
    <FilesMatch "\.(php|phtml|phar|cgi|pl|py|sh)$">
        Require all denied
    </FilesMatch>

    <IfModule mod_headers.c>
        # Security headers
        Header always set X-Content-Type-Options "nosniff"
        Header always set X-Frame-Options "DENY"
        Header always set Referrer-Policy "strict-origin-when-cross-origin"
        Header always set Content-Security-Policy "default-src 'self'; img-src 'self' data:; script-src 'self'; style-src 'self'; font-src 'self'; frame-src https://www.youtube-nocookie.com; object-src 'none'; base-uri 'self'; frame-ancestors 'none'"
        Header always set Strict-Transport-Security "max-age=31536000"

        # Caching
        <FilesMatch "\.(css|js|woff2|webp|jpg|jpeg|png|svg)$">
            Header set Cache-Control "public, max-age=31536000, immutable"
        </FilesMatch>
        <FilesMatch "\.(html|xml|json)$">
            Header set Cache-Control "no-cache"
        </FilesMatch>
        <FilesMatch "\.(pdf|mp4|webm)$">
            Header set Cache-Control "public, max-age=86400"
        </FilesMatch>
    </IfModule>

    # Uploaded materials: never run scripts, download office/archive files
    <Directory /var/www/quantum/materials>
        Header always set Content-Security-Policy "sandbox"
        <FilesMatch "\.(zip|docx|pptx|xlsx)$">
            Header set Content-Disposition "attachment"
        </FilesMatch>
    </Directory>
</VirtualHost>
```

Notes:
- HSTS is set **without** `includeSubDomains`; the policy for the parent `phys.uni-sofia.bg` is the sysadmin's decision.
- Long cache for CSS/JS is safe because Hugo fingerprints asset filenames (`style.<hash>.css`).
- PDFs get a short cache because a lecturer may re-upload a file under the same name.
- If YouTube embeds are not used, drop `frame-src`.

## 13. Security model

**Principle:** the deploy writes whatever is in the repository into the docroot. Anyone with write access to the repo — including every Pages CMS collaborator, or whoever steals their account — can publish arbitrary files. Protection therefore lives in three layers: **server config (§12)**, **CI checks (§11.1)**, **accounts**.

| Risk | Impact on wider phys.uni-sofia.bg | Mitigation |
|---|---|---|
| Server-side code execution (`.php`, `.htaccess`) | Server compromise → other faculty sites | Static-only vhost, `AllowOverride None`, deny script extensions, CI forbids such files |
| Symlinks exposing server files | Leak of `/etc/...`, other sites' files | `-FollowSymLinks`, `core.symlinks false`, CI rejects symlinks |
| XSS / phishing via uploaded html/svg | Same-site subdomain: cookie tossing for `.phys.uni-sofia.bg`, CSRF against other faculty apps, fake login pages on a trusted domain | CI extension allowlist, CSP, `sandbox` CSP on `/materials`, `nosniff` |
| Malware hosting | Safe Browsing blocklisting can affect the whole domain | Allowlist (no executables), size limits, push notifications to maintainers |
| Compromised editor account | Defacement / abuse of content | GitHub org 2FA mandatory; Pages CMS logins are as strong as the editor's email; Git history = audit trail, revert in seconds |
| Supply chain in CI | Malicious build output | Actions pinned by SHA, pinned Hugo version |
| Server-side deploy | Lateral movement | Dedicated Unix user, no access to other docroots, cron not as root, read-only deploy key |

Compared with WordPress (PHP + plugins → server-side code execution, a frequent compromise vector on university servers), the worst realistic case here is defaced or abused content on one subdomain, not a server breach.

## 14. SEO and quality

- Semantic HTML, `lang` attributes, `hreflang` for BG/EN.
- `sitemap.xml` and `robots.txt` (Hugo built-in).
- Open Graph meta, schema.org JSON-LD: `EducationalOrganization`, `Person`, `Course`.
- Responsive images with `srcset`; lazy loading.
- Targets: Lighthouse ≥ 95 (Performance, Accessibility, SEO); WCAG 2.1 AA contrast.
- Optional: self-hosted KaTeX for formulas.
- After launch: Google Search Console, submit sitemap.

## 15. Roles and editorial workflow

| Role | Who | Access |
|---|---|---|
| Owner / maintainer | Site maintainer + at least one more owner | GitHub org owner; code, layouts, CI |
| Editor | Selected colleagues | Pages CMS: all collections (news, research, static pages) |
| Lecturer | Every lecturer | Pages CMS: own profile, courses, uploads to own materials folder (by convention) |

- Every save in Pages CMS is a commit with the editor's name.
- Maintainers receive GitHub notifications for every push to `main`.
- Per-folder permissions are not enforced technically; the convention "edit only your own space" applies, backed by history and revert.
